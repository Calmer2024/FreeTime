# FreeTime UI/UX 组件规范

## 目的与适用范围

本规范定义 FreeTime 各应用共享的交互与视觉约束。新增组件必须遵循；修改既有组件时，应在当前改动范围内逐步迁移，避免为了统一样式扩大无关重构。

本轮落地范围仅限 DrillKnowledge 的并行任务组件：应用“CRUD 原地操作”规范，并同步将任务条目改为纯白填充、修复错误任务条目的布局。下拉菜单规范本轮只完成定义，不改造其他既有组件。

## 1. 下拉菜单与浮层

### 1.1 布局模型

- Dropdown Menu、Popover、Context Menu 等临时内容必须作为悬浮图层覆盖在页面内容上。
- 浮层使用 `position: absolute` 或 `position: fixed`，不得参与普通文档流，不得撑高、撑宽或切开所属卡片。
- 触发器所在容器仅用于定位锚点；浮层不得因嵌套位置被父级 `overflow: hidden` 裁切。无法避免裁切时，应将浮层挂载到更高层容器。
- 浮层默认从触发器外沿留出 6–10px 间距，并根据视口空间选择向上或向下展开。

### 1.2 层级与投影

- 普通页面内容使用基础层级；粘性顶部栏高于内容；Dropdown/Popover 必须高于顶部栏内普通控件。
- 推荐层级：顶部栏 `z-index: 100`，Dropdown/Popover `z-index: 1000`，Modal/Dialog `z-index: 1200`。
- 浮层必须具有清晰投影和实体背景，推荐：

```css
box-shadow: 0 18px 55px rgba(24, 26, 23, 0.16);
background: rgba(255, 255, 255, 0.97);
```

- 投影用于表达图层关系，不应用重边框代替；边框仅作为浅色轮廓。

### 1.3 开合与可访问性

- 触发器提供 `aria-expanded` 和 `aria-controls`，开合状态必须同步更新。
- 点击浮层外部或按 `Escape` 应关闭浮层。
- 浮层关闭后不得保留不可见但可聚焦的交互元素。
- 动画仅使用轻量透明度与位移，不改变页面布局。

## 2. CRUD 原地操作

### 2.1 基本原则

- 创建、查看、编辑、删除等列表级操作优先在当前条目内完成。
- 点击 CRUD 图标后，不得为了确认或编辑额外打开 Modal/Dialog、气泡确认框或独立卡片。
- 文本编辑应在原文本位置切换为输入控件；删除确认应在原操作槽内切换图标状态。
- 状态切换不得推动相邻内容、改变条目宽度或导致列表抖动。

### 2.2 删除操作

- 默认状态显示删除图标。
- 第一次点击后，删除图标所在操作槽原地切换为“确认”和“取消”两个图标按钮。
- 不额外渲染“确定删除？”文字、带背景的确认容器或提示气泡。
- 确认按钮使用明确的危险色或确认语义图标；取消按钮使用中性色。
- 点击确认后才执行持久删除；请求失败时恢复默认操作状态，并在条目自身的错误消息区域显示失败原因。
- 点击取消后直接恢复删除图标，不产生后端请求。

### 2.3 查看与编辑操作

- 查看属于无破坏性即时操作，不增加确认步骤。
- 查看按钮应保持稳定位置；进入查看状态后可用选中态表达当前项目，但不得覆盖其他 CRUD 操作。
- 编辑按钮触发后，内容在原位置切换为输入控件，操作槽切换为保存/取消。

### 2.4 操作槽

- 每个条目应为 CRUD 操作预留固定宽度的操作槽。
- 图标按钮尺寸、间距和焦点轮廓保持一致。
- 图标切换必须更新 `aria-label` 和 `title`，让辅助技术能区分删除、确认和取消。
- 异步操作期间只禁用相关条目的操作，不锁定整个列表。

## 3. DrillKnowledge 并行任务专项约束

### 3.1 条目视觉

- 所有任务条目使用纯白色背景 `#ffffff`。
- 状态通过图标、文字颜色和必要的浅色边框表达，不使用大面积状态底色。
- 任务条目保持紧凑，但必须为错误信息和 CRUD 操作保留稳定布局。

### 3.2 错误任务

- 外层错误状态类使用 `.task-card.task-error`；错误文本使用独立类 `.task-error-message`，禁止两者复用同一类名。
- 第一行继续展示状态、任务名称、进度、耗时和操作槽。
- 错误文本位于第二行，跨越任务名称到操作区，可换行并最多显示两行。
- 超出两行时截断显示，完整错误信息写入 `title` 供悬停查看。
- 删除请求本身的错误也复用错误消息区域，不创建额外浮层。

### 3.3 CRUD 切换

- 默认操作槽展示可用的“查看”按钮和删除图标。
- 点击删除图标后，仅当前条目的操作槽切换为确认与取消图标；其他条目不变。
- 确认/取消图标保持在删除操作所在区域，不出现 `.inline-confirmation` 气泡容器。
- 切换前后操作槽宽度固定，任务名称、进度和耗时不得位移。

## 4. 验收检查表

- Dropdown/Popover 是否覆盖内容而非撑开卡片？
- 浮层是否具有实体背景、投影和高于普通内容的层级？
- CRUD 操作是否在原条目内完成且未使用 Modal/Dialog？
- 删除图标是否原地切换为确认/取消，且没有额外气泡框？
- 切换操作状态时条目是否无位移、无尺寸跳变？
- 错误状态类与错误消息类是否职责分离？
- 长错误文本是否限制两行且不破坏操作槽？
- 所有图标按钮是否具有准确的 `aria-label` 和键盘焦点状态？
