# 小红书帖子类型与上游解析适配报告

> 调查与实现日期：2026-08-01
> 调查口径：公开可分享、以“笔记 URL”为主体的内容单元。直播间、用户主页、专辑、搜索结果和评论页不是帖子类型，不纳入本次笔记解析管线。

## 一、结论摘要

小红书帖子不应只按“视频 URL”处理。当前可确认的主体内容类型为：

| 主体类型 | 平台依据 | 上游资源结构 | MiMo Trust 处理策略 |
|---|---|---|---|
| 图文笔记 | 分享开放平台定义图文笔记为 1–18 张图片；deeplink `normal` | 标题、完整正文、1–18 张图片、封面、话题 | 下载全部图片，逐图 OCR/视觉理解，与完整正文合并 |
| 视频笔记 | 分享开放平台定义单视频+可选封面；deeplink `vedio` 和视频 Feed | 标题、正文、单视频、多清晰度流、封面 | 复用字幕；否则完整 ASR；必要时关键帧和全视频理解 |
| 长文笔记 | 2026 年官方活动明确接受“长文笔记”；deeplink `multi` / `multi_note` | 长正文，可能附带排版图片或分页图 | 保留完整正文，不再截成 1500 字；附图逐图 OCR |
| 实况照片笔记 | 设备厂商官方接入说明显示可把动态照片发布到小红书；内容结构是静态主图+短动态轨 | 一组静态图片，其中部分图片带对应动态视频片段 | 静态帧全部 OCR；每段动态轨单独以 1 FPS 理解，再按图片顺序合并 |

官方开放 SDK 对外暴露的一级发布类型仍是“图文”和“视频”，并规定两者同时传入时按图文处理。长文是独立的产品呈现类型；实况照片在解析架构中应视为图文的动态媒体子型，而不是普通视频笔记。[小红书分享开放平台 Android 文档](https://agora.xiaohongshu.com/doc/android)、[小红书 deeplink 规范](https://pages.xiaohongshu.com/activity/deeplink)、[小红书 2026 高考季活动规则](https://fe.xiaohongshu.com/ditto/vincent/adec82d954a84a9486514c0a09e5f6d6?fullscreen=true&naviHidden=yes)、[vivo 动态照片分享说明](https://bbs.vivo.com.cn/newbbs/thread/37724577)

## 二、哪些不是新的主体解析类型

以下是附着在笔记上的业务或语义属性，应进入 `source_context`，不应复制一套媒体解析管线：

- 商品笔记、导购笔记：主体仍是图文、视频或长文，额外挂载商品卡片。
- 地点/探店笔记：主体媒体不变，额外挂载 POI/门店信息。
- 话题、@用户、品牌合作、商业合作：属于发布上下文和披露信息。
- Guang 视频、短视频 Feed：属于视频分发/展示入口，媒体处理仍走视频笔记管线。

小红书官方产品资料说明笔记详情页可包含用户、地点、标签、相关商品和相似笔记；官方商品资料也把商品笔记定义为带商品卡片的笔记。因此附件应参与信源核验上下文，但不能被当作主体正文证据。[小红书笔记产品资料](https://rpdc.xiaohongshu.com/article_detail/43)、[商品笔记定义](https://miniapp.xiaohongshu.com/third/api-3rd-doc/productionHalf)、[小红书本地生活](https://life.xiaohongshu.com/app-account/)

## 三、原管线问题复现

原实现把所有小红书链接交给 yt-dlp 视频提取器：

1. 视频笔记可以返回视频 formats，通常能够继续处理。
2. 图文笔记只返回图片缩略资源，没有 `note_images`，随后被误判成视频并尝试下载音视频流。
3. 长文正文进入发布上下文时只保留前 1500 字。
4. 实况照片的动态轨没有独立字段，动态信息完全丢失。
5. `/discovery/item/<id>` 与 `/explore/<id>` 未统一；若删除 `xsec_token`，部分公开分享页会返回 `300031`。
6. 商品、地点、话题等上下文没有进入标准输入。

根因是“平台识别”和“帖子类型识别”耦合在通用视频提取器内，没有小红书 note-level 适配层。

## 四、已经落地的解决方案

### 4.1 独立小红书上游适配器

新增 `app/xiaohongshu.py`：

- 解析页面 `window.__INITIAL_STATE__`，按 note ID 定位笔记详情；
- 识别 `normal / video / vedio / multi / multi_note / long`；
- 输出统一的 `note_images`、`formats`、`live_photo_videos`；
- 输出 `source_subtype`：
  - `xiaohongshu_image_note`
  - `xiaohongshu_video_note`
  - `xiaohongshu_long_note`
  - `xiaohongshu_live_photo_note`
- 抽取话题和商品、地点、品牌、合作、@用户等附件名称到 `source_context`；
- 支持 Netscape Cookie 文件作为公开页面会话兼容路径；
- 登录验证、私密、删除或状态数据缺失时返回明确的受限错误。

### 4.2 URL 规范化

- `/discovery/item/<id>` 统一到 `/explore/<id>`；
- 删除普通追踪参数；
- 保留网页访问可能必需的 `xsec_token` 和 `xsec_source`；
- 短链仍逐跳执行公网地址和平台域名校验。

### 4.3 分类型管线

- 图文：下载全部静态图片并逐图分析。
- 视频：沿用字幕 → ASR → 关键帧 → 全视频升级链路。
- 长文：完整正文进入结构化模型，附图仍逐图分析。
- 实况：静态图片和动态轨同时处理；动态轨最大并发为 3，每段独立记录成功或失败。
- 附加卡片：写入“发布上下文”，供主张拆分判断推广关系、地点和来源身份。

## 五、验证结果

- 新增 7 项小红书专项测试：四种主体类型、上下文附件、URL 规范化、适配器优先级和实况动态轨分析。
- 全项目测试：67 项通过。
- `git diff --check` 无空白错误。

真实网络探测能够复现小红书对缺少有效访问参数/会话的页面返回 `300031`。由于公开页面会随笔记状态、临时 token、登录验证和风控策略变化，fixture 测试负责锁定数据协议；线上验收仍应准备每种类型各 2–3 条当前有效、授权访问的样本 URL。

## 六、仍需遵守的边界

- 不绕过验证码、登录、私密、删除、地区或账号权限。
- `xsec_token` 只用于访问用户提交的分享页，不视为长期稳定 URL。
- 页面 JSON 是平台内部网页协议，可能变化；解析失败必须降级并告警，不能把空媒体列表声明为完成。
- 商品/地点卡片只能证明帖子挂载了相应对象，不能单独证明正文中的事实主张。
