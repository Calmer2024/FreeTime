# DrillKnowledge 全文整理恢复设计

## 目标

修复 MiMo 严格 JSON Schema 生成被 `abort` 中止后，DrillKnowledge 将 ASR 原文误当成“完整全文”并标记“需要复核”的问题，同时不改变公开 API、前端数据结构或已安装应用。

## 根因约束

- 目标抖音视频可以完成 URL 解析、音频下载和完整 ASR，故障仅发生在 MiMo 阅读结果生成阶段。
- 当前复合 Schema 同时约束文章、资源和观点对象；提示词与 Schema 字段顺序、枚举取值不完全对齐时，MiMo 返回 `finish_reason="abort"` 和残缺 JSON。
- 当前实现只识别 `length`，随后把残缺 JSON 解析错误包装成泛化消息，并进入本地原文清洗降级。

## 设计

### 阅读结果边界

首个 MiMo 请求只负责四个字段，并按固定顺序生成：`summary`、`key_points`、`topics`、`article`。资源链接继续由现有本地 URL 提取逻辑处理；观点判断继续由现有独立联网评估请求处理。这样保留现有输出契约，同时移除容易触发严格解码中止的嵌套对象和枚举。

提示词必须给出精确 JSON 字段顺序，并明确不得增加字段。文章仍须保留完整信息和 Markdown 结构。

### 未完成响应恢复

阅读结果生成把 `stop` 作为唯一完整结束状态。`abort`、`length` 或其他结束原因均不得进入 JSON 解析。

首次响应未完成或 JSON 损坏时，执行一次重试。重试使用同一精简 Schema，并增加短而明确的结构指令；不携带残缺输出，避免污染下一次生成。第二次仍失败时抛出包含结束原因的 `MimoError`。

### 降级语义

若两次生成均失败，继续保留 ASR 原文，避免丢失内容；覆盖状态保持 `needs_review`。覆盖说明必须明确“全文整理失败，当前展示 ASR/提取原文”，不得声称已整理为可阅读文章。

## 测试

- 单元测试模拟首次 `abort`、第二次 `stop`，断言返回第二次的合法阅读结果并执行两次请求。
- 单元测试模拟连续 `abort`，断言错误包含 `abort`，且不会尝试解析残缺 JSON。
- 单元测试检查发送给 MiMo 的 Schema 只包含四个阅读字段。
- 流水线测试模拟持续失败，断言 `needs_review`、本地原文保留和准确降级提示。
- 完成单元测试后，以目标抖音链接执行一次隔离真实链路，核对状态、Markdown 文章结构、摘要和关键点。

## 非目标

- 不调整 ASR、关键帧或抖音 Cookie 获取策略。
- 不修改前端布局。
- 不发布、不打包、不更新已安装应用。
