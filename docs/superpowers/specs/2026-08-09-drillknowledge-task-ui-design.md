# DrillKnowledge 并行任务与下载反馈优化设计

## 目标

在不改变现有提取数据、任务状态、任务进度及结果展示能力的前提下，压缩下载反馈、将并行任务提升为顶栏悬浮组件，并消除并行提取期间“查看”结果与提取过渡层同时显示或互相覆盖的问题。

本次仅提供本地开发预览供验收，不构建安装包、不发布版本，也不更新已安装的 FreeTime 应用。

## 交互设计

### 一键下载

- “一键下载”开始后，只在按钮内部显示旋转图标和简短状态文字，例如“保存中 2”。
- 下载结束后，在资源操作区显示紧凑的单行成功或失败反馈；不再渲染占据内容区域的大块加载组件。
- 保留现有下载目录设置、批量保存数量、目标目录及失败数量信息。
- 下载进行中禁用重复触发，结束后恢复按钮可用状态。

### 并行任务入口与面板

- 在顶部栏右侧放置一个圆形任务按钮，与搜索栏和现有导航保持同一视觉层级。
- 按钮使用任务图标；存在运行中或排队中任务时显示数量徽标和轻量活动状态。
- 点击按钮展开或折叠右对齐的悬浮面板。面板使用高层级定位，不占用主内容区高度，也不推动结果布局。
- 面板最大高度为 360px，并受当前视口可用高度约束；任务列表独立纵向滚动。
- 保留任务状态、输入名称、进度、耗时、错误和“查看”操作。
- 成功与失败均视为已结束记录，显示删除按钮。运行中和排队中的记录不可删除。
- 删除操作同时更新浏览器任务记录与后端持久任务记录，刷新页面后不恢复被删除记录。
- 删除当前正在查看的任务记录只删除队列记录，不清空已渲染结果。
- 当不存在任何任务记录时，隐藏悬浮面板并隐藏任务按钮。

### 并行结果查看

- 每次提交一批新任务时，允许现有提取过渡组件作为“尚无结果”的反馈。
- 任意任务结果被自动展示或用户点击“查看”后，立即关闭提取过渡组件，结果区域成为唯一主内容。
- 其他任务继续运行时，其进度仅在顶栏并行任务面板中展示，不重新打开主内容提取过渡组件。
- 用户点击“查看”会建立明确的用户选择；同批次中稍后完成的任务不得自动覆盖该结果。
- 新的一次主动提交会清除上一批次的用户选择锁定，并重新进入等待首个结果的状态。
- 在没有用户选择时，仅首个成功结果自动展示一次；后续完成结果保留在任务面板中供查看。

## 状态与数据流

- 前端任务记录继续以 `taskRecords` 为数据源，并保留现有 localStorage 恢复和后端轮询机制。
- 新增独立的面板展开状态，以及“当前是否由用户明确选择结果”的展示状态，避免用全局任务运行状态控制结果可见性。
- 下载反馈仅属于资源操作区，不复用提取过渡组件。
- 后端新增删除单个任务记录的接口。接口仅允许删除 `success` 或 `error` 状态记录；不存在时返回 404，非终态任务返回 409。
- 删除成功后持久化任务文件；前端只有在服务端删除成功后才从任务列表移除，失败时保留记录并显示轻量错误反馈。

## 视觉与可访问性

- 圆形任务按钮提供随展开状态变化的 `aria-label`、`title` 和 `aria-expanded`。
- 悬浮面板与按钮建立 `aria-controls` 关系，键盘可聚焦所有操作。
- 删除按钮提供明确的任务名称上下文；使用紧凑的二次确认，防止误删。
- 下载反馈区域使用 `aria-live="polite"`，不会抢占焦点。
- 窄窗口下任务面板与视口左右保持安全间距，宽度不超过可用视口。

## 错误处理

- 下载失败时恢复按钮可用状态，并展示后端返回的错误消息。
- 删除接口失败时不提前移除前端记录，并在对应任务行显示或关联紧凑错误提示。
- 任务轮询与页面恢复继续容忍临时网络错误，不影响已存在的本地记录。

## 验证策略

- 前端行为测试覆盖：按钮/面板展开状态、受限高度与滚动容器、终态删除入口、运行中任务不可删除、用户查看时关闭加载层、后续完成结果不覆盖用户选择，以及下载反馈保持紧凑。
- 后端测试覆盖：成功删除终态记录、拒绝删除运行中记录、删除不存在记录，以及删除结果写入持久任务文件。
- 回归运行现有 Python 与桌面端测试，并执行前端语法检查。
- 启动本地开发服务，在未安装版本中完成多任务、查看、删除和一键下载的人工验收。

## 范围外事项

- 不改变提取管线、任务并发策略、结果数据结构或下载文件内容。
- 不清理历史任务、不增加批量删除。
- 不构建安装程序，不调整应用版本号，不执行发布或增量更新。
