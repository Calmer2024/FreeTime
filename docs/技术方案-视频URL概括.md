# MiMo Trust「信息提取」技术方案

## 1. 目标与边界

输入抖音、哔哩哔哩或 YouTube 公公开视频、抖音图文作品、平台短链或手机分享文案，输出：

1. 原文层：`full_source_text` 保存可回溯的原始提取层；`cleaned_article` 去除时间码、传输标签、重复 OCR 和截断碎片，并使用不丢字符的中文连续文本分句器按发布内容、口播字幕与画面信息重组；
2. 阅读层：内容概括、重点和主题；
3. 下游结构层：固定四字段 JSON。

本节点只表达“内容说了什么”，不判断内容真假。所有值得外部核验的事实性陈述统一进入“原子主张”；“隐性观点”是内容措辞所表达或暗示的立场。

## 2. 下游标准 JSON

```json
{
  "case_id": "watermelon-seed-rumor",
  "内容主题": "无籽西瓜、白籽西瓜食品安全谣言核验",
  "原子主张": [
    "使用激素喷洒雌花培育的西瓜，其种子会变白、萎缩并失去繁殖能力"
  ],
  "隐性观点": [
    "无籽西瓜和白籽西瓜对儿童健康有害",
    "人工干预培育出的农作物不安全"
  ]
}
```

字段语义：

- `case_id`：稳定、可读的英文 kebab-case 案例标识；
- `内容主题`：一句话描述该内容围绕的核实主题；
- `原子主张`：提取全部具体、独立且值得通过外部资料核验的关键断言；
- `隐性观点`：提取全部有充分上下文依据、但作者没有直接明说的立场或潜台词；没有可靠潜台词时为空。

两类数组不设置固定条目数量，根据实际内容有多少输出多少；仍保留单条文本质量、去重和严格类型约束。

原子主张采用“自适应语义密度”控制，而不是硬编码数量：

1. 根据有效原文长度、视频时长和图文页数计算建议密度，短单主题内容通常更低，长视频和多图内容自动提高；
2. 建议密度不是 Schema 上限，新增条目如果代表独立核心事件或不同核验路径，允许超过；
3. 同一事件链的实施方式、累计金额、用途和直接结果合并为最小充分核验单元；
4. 特定时间地点且需要独立信源的事件单独保留；
5. 本地质量门只检测流水账、代词依赖、高重叠和跨条重复数字，不按建议值裁剪内容；
6. 只有语义重压缩结果的风险严格下降时才替换原结果。

这些定义及文档示例是语义类比，不是关键词规则。系统不在 Pydantic 或管线中维护领域词表、媒体元信息黑名单或“严肃新闻强制清空”等语义覆盖逻辑。

## 3. 真正的结构化输出

结构保障分为三层，不依赖“请输出 JSON”这一句提示：

1. MiMo Chat Completions 请求传入 `response_format.type=json_schema`；
2. `json_schema.strict=true`，限制必填字段、类型、数组长度、唯一项、`case_id` 格式并禁止额外字段；
3. 服务端使用 Pydantic `StructuredInformation` 按同一协议再次验证、清理空项和去重。

如果 `finish_reason=length`、返回空内容、JSON 损坏或 Schema 不合法，系统只执行一次同样受严格 Schema 约束的修复。修复器只能补齐结构或删除截断尾项，不能增加输入中不存在的事实。再次失败时，系统保留完整原文，并生成合法的保守结构：主题取标题，两个语义数组全部留空，覆盖状态标记为 `needs_review`。

## 4. 自适应执行管线

```text
手机分享文案 / URL
  -> 抽取 HTTP(S) 地址
  -> 短链逐跳安全展开
  -> 规范化稳定作品 URL
  -> 内容形态分流
      ├─ 视频：元数据、字幕、音频活动
      └─ 图文：作品 JSON、全部原图
  -> 短路式降级处理
      ├─ 完整平台字幕可用：直接进入结构化转换
      ├─ 无字幕但有口播：完整分段 ASR 后直接进入结构化转换
      ├─ 无有效口播：场景变化/周期关键帧 OCR
      ├─ OCR 仍不足：按配置升级全视频多模态
      └─ 图文作品：全部图片 OCR 与视觉理解
  -> 合并为 full_source_text
  -> 严格 Schema 结构化转换
  -> 服务端二次校验
  -> 持久化并向下游输出
```

### 分享链接解析

- `b23.tv/{code}` 展开为 B站 BV 长链；
- `v.douyin.com/{code}` 展开为抖音作品页；
- `/video/{id}` 进入视频管线；
- `/note/{id}` 且 `awemeType=68` 进入图文轮播管线；
- 每一跳请求前校验平台白名单、DNS 和公网 IP，最多五跳。

### 图文轮播

系统读取抖音页面内嵌作品数据并下载全部图片。图片以最多 8 张一批、最多 2 批并发执行 OCR 和视觉理解。所有原始 OCR 和画面观察保存在 `keyframes`，同时进入 `full_source_text`，不伪造成视频时间轴。

## 5. 四级成本阶梯

| 层级 | 内容 | 触发 |
|---|---|---|
| L0 | 缓存、URL、平台元数据、字幕存在性 | 所有请求 |
| L1 | 平台字幕解析与音频活动探测 | 首次解析 |
| L2 | 完整 ASR；仅在无有效口播时执行关键帧 OCR；严格结构化转换 | L1 未直接取得完整文本 |
| L3 | 全视频低帧率多模态理解 | 显式全模态或 OCR 仍不足 |

降本规则：

- 相同规范化 URL 和模式复用新协议缓存；
- 有完整字幕不做 ASR；
- 字幕或 ASR 已获得有效口播文本时，不下载视觉轨、不抽取关键帧；
- 静音视频跳过 ASR；
- 无有效口播的视频才执行场景变化与周期兜底帧 OCR；
- 图文不下载或转码虚假视频流；
- 结构修复只在首次输出无效时调用一次。

## 6. 覆盖与失败语义

- `structured_ready`：完整原文已取得，严格结构化数据生成成功；
- `partial`：某个活跃模态覆盖不足，但仍返回现有原文和结构；
- `needs_review`：模型结构化失败，已返回本地保守结构；
- `no_structured_information`：输入中没有形成任何结构化条目；
- `metadata_only`：没有模型能力，只返回元数据或本地预览；
- `unavailable`：作品不可访问。

下游必须同时读取 `coverage.status` 和 `critical_gaps`，不能把结构化主张误解为已经核真的外部事实。

## 7. 持久化与接口

- SQLite：`.cache/video_summary.sqlite3`
- `POST /api/analyze`：执行信息提取
- `GET /api/videos`：列出持久化结果
- `DELETE /api/videos/{cache_key}`：删除单条
- `DELETE /api/videos`：清空全部

缓存身份包含协议版本 `structured-information-v4`。启动时删除所有不属于当前协议版本的历史缓存，避免旧结构继续流向下游。

## 8. 当前验收指标

- 完整语音覆盖率；
- `cleaned_article` 相对字幕/ASR 的全文重组保留率；低于 99% 时加入关键缺口并降为 `partial`；
- 逐帧/逐图 OCR 覆盖率；
- 原文保留完整率；
- 原子主张语义完整率与去重率；
- 原子主张与隐性观点归类准确率；
- JSON Schema 一次成功率、修复率和本地降级率；
- 单视频成本及 P50/P95 延迟；
- 下游反序列化成功率必须为 100%。
