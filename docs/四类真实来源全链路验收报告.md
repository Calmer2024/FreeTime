## 发现的问题与解决方案

### 快手 `/f/` 分享路径无法解析

问题：`/f/{shareToken}` 未被识别为短链；即使进入适配器，也会在取得作品 ID 前要求 `/short-video/{photoId}`。原实现还先访问首页并在导航 GET 中携带 `Origin/Referer`，导致平台返回不同页面或验证码。

解决：

- 将快手 `/f/` 纳入逐跳安全展开；
- 跟随 302 得到稳定 `/short-video/{photoId}`；
- 使用完整浏览器 UA 和正常导航请求头；
- 优先解析页面内 `window.__APOLLO_STATE__`，直接取得标题、作者、时长、封面和 MP4；
- 只有页面态缺失时才回退 GraphQL 和会话错误处理。

### 小红书标题为空

问题：该笔记的 `note.title` 为空，真实标题位于正文第一行，旧代码输出默认“小红书笔记”。

解决：显式标题为空时使用正文首个非空行，并保留完整正文、3 张图及话题上下文。

### 完整图文被错误要求“全视频补充”

问题：图文事故图片被分类为 `event_footage` 后，视频覆盖逻辑错误地追加“事件型视频的全视频多模态补充未完成”，将完整图文标记为 `partial`。

解决：全视频缺口只对非图文内容生效；新增回归函数和测试。原始小红书样本重跑后为 `structured_ready`、`critical_gaps=[]`。

### 微博无视频格式被当作解析失败

问题：输入实际是正文加 2 图的普通微博。yt-dlp 已取得状态 JSON，却因没有视频格式抛出错误，导致图文内容无法进入 OCR。

解决：

- 对标准 `/{uid}/{mblogid}` 状态页前置读取微博访客详情；
- 解析 `text_raw`、用户与 `pic_infos` 原图；
- 归一化为 `weibo_image_post`；
- `/tv/show/...` 仍保留原有视频提取器，并已验证可返回 3 个视频格式；
- 消除成功回退前的假错误日志。

### 视频号 `/sph/` 未进入专用适配器

问题：`weixin.qq.com/sph/{shortUri}` 不在平台允许列表，重定向后的 `/finder-preview/pages/sph?id=...` 也不在旧适配路径；通用提取器返回 `Unsupported URL`。

解决：

- 将 `weixin.qq.com` 纳入平台安全域和短链识别；
- 安全展开到 `channels.weixin.qq.com`；
- 复现浏览器公开请求，使用同一页面会话 POST 官方 `get_feed_info`；
- 按实际响应区分视频与图文。该样本没有视频流，正确归一化为 `wechat_channels_image_post`，而不是误报视频失败。
